# Quick Task 260811-w4d: Watchdog must diagnose a dead PAT, not call it "throttling"

## Problem

Approved post `diktum-aug11-nedoslushivayut` failed to publish. In the TG
«Планировщик» channel the operator saw:

```
❌ Не удалось дёрнуть publish.yml: GitHubAPIError            (12:04)
🐕 Watchdog: preview_bot cron throttled                     (13:24, 13:34)
   ⚠️ dispatch failed: HTTP 401: {"message":"Bad credentials", ...}
   GH Actions scheduled workflows иногда пропускают тики при высокой
   нагрузке — это известное поведение, не баг pipeline. Watchdog
   восстанавливает.
```

Root cause: the `BOT_DISPATCH_PAT` secret (fine-grained PAT, 90-day life)
**expired / was revoked**. Every dispatch — the approve button's
`publish.yml` call and the watchdog's `preview_bot.yml` call — uses that one
PAT, so all return `HTTP 401 Bad credentials`.

The pipeline damage was made worse by a **watchdog code bug**:
`preview_watchdog._alert` appends the reassuring footer *"GH throttling —
known behavior, not a bug, watchdog recovers"* on **every** failure, including
a `401 Bad credentials`. So the alarm actively told the operator the pipeline
was fine while the credential was dead — hiding the real, action-required
cause (rotate the secret).

## Fix contract

In `src/preview_watchdog.py`, detect auth-failure dispatch errors
(`HTTP 401`, `HTTP 403`, or `bad credentials`, case-insensitive) via a small
`_is_auth_failure(err)` helper. When the dispatch failed AND it is an auth
failure, `_alert` must send a distinct message:

- title: `🔴 Watchdog: BOT_DISPATCH_PAT мёртв`
- footer: states the token expired/was revoked (401/403 Bad credentials),
  that this is **NOT** GH throttling, that the approve button + auto-preview
  are down until the secret is rotated, and gives the exact fix command
  `gh secret set BOT_DISPATCH_PAT -R <owner>/<repo>`.

All other paths (dispatch OK = real throttle; non-auth dispatch failure like
`HTTP 500`/timeout) keep the existing throttle wording unchanged. Watchdog
still exits 0 always.
