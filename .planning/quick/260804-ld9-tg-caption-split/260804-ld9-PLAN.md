# Quick Task 260804-ld9: Split long TG posts (caption >1024) in production

## Problem

Approved post `lapulya-aug4-stress` failed to publish. `publish` workflow run
[30894608324](https://github.com/Carbon1777/forton-lab-marketing/actions/runs/30894608324)
(2026-08-04 12:03 МСК) crashed:

```
WARN: lapulya-aug4-stress.md: caption 1044 > 1024; Telegram will reject.
FAIL lapulya-aug4-stress.md: 400 Bad Request for url: .../sendPhoto
```

Root cause: **preview↔production divergence**. `src/preview_bot.py` already
splits a body >1024 into two messages (text + photo/video) via
`_send_split_photo` / `_send_split_video`. But `src/tg_post.py` (the real
publisher) only logs a WARN and still sends the full caption in one `sendPhoto`
/`sendVideo` — Telegram rejects any caption >1024 with HTTP 400, the run exits
1, and nothing publishes.

## Fix contract

In `src/tg_post.py`, when `len(body) > TG_CAPTION_LIMIT` on a photo/video post:
send the media with an **empty caption**, then send the full body as a separate
`sendMessage`. Mirrors `preview_bot.py` so preview and production stay in sync.
The media send stays the "primary" message (its `message_id` / `ok` is what
`publish_one` inspects and reports). No warning meta-text goes to the public
channel (that badge was preview-only).

Guard: if the split body itself exceeds `TG_TEXT_LIMIT` (4096), keep the
existing hard-fail — a body that large is a real content problem, not a caption
limit.
